## 先说结论

我现在的主力组合是：**一个终端 Agent + 一个 IDE 补全 + 免费对话模型**。

- 日常写业务代码：**Copilot** 做补全，成本低、干扰小
- 重构/跨文件改造：**Claude Code** 或 **OpenCode** 这类终端 Agent
- 大段代码审阅、方案讨论：**Cursor** 的代码库上下文更顺手
- 查资料、生成图片、临时问答：豆包 / DeepSeek / ChatGPT / Gemini 免费额度

如果只保留一个付费工具，我会选**能读整个仓库、能执行命令的 Agent**，而不是单纯的补全。

下面是我 2026 年的实际月支出和使用感受。价格会变，按你自己的账单为准。

## 一、月成本对比

| 工具 | 我的月支出 | 主要用途 | 最大优点 | 最大问题 |
|---|---:|---|---|---|
| GitHub Copilot | ¥70 | IDE 补全、小功能 | 稳定、支持主流 IDE、模型更新快 | 跨文件改造偏弱 |
| Cursor | ¥140 | 代码库问答、Agent | 上下文和交互顺手 | 贵，重度使用会限流 |
| Claude Code | ¥50（中转） | 终端 Agent、重构 | 长任务能力强、可接 Skill | 中转稳定性和数据合规要评估 |
| OpenCode | ¥40 | 终端 Agent、国内模型 | 模型选择灵活、成本低 | 生态和文档还在完善 |
| 豆包 / DeepSeek / ChatGPT / Gemini | ¥0 | 问答、查资料、图片 | 免费够用 | 不能替代仓库级 Agent |

> 说明：Claude Code 和 OpenCode 的费用来自第三方中转/国内模型套餐，不是官方直连价格。中转渠道有稳定性、隐私和封号风险，企业项目不要把敏感代码发到不可控渠道。

## 二、逐个说使用感受

### 1. GitHub Copilot：最稳的“默认补全”

Copilot 这两年存在感被 Agent 抢了不少，但它的优势还在：

- 主流 IDE 都支持，装完就能用
- 补全延迟低，不打断思路
- 小函数、单测、注释、正则这类“小活”很顺
- 支持较新的模型，复杂问题也能切对话模式

适合：**每天都在 IDE 里写代码的人**。它不负责“帮你把整个需求做完”，但能明显减少敲键盘的时间。

不适合：跨十几个文件的重构、需要跑命令验证的任务。

### 2. Cursor：代码库上下文最顺

Cursor 的强项是“把仓库当成上下文”：

- `@Codebase` 问“这个接口的鉴权链路在哪”，比纯聊天准确
- Agent 模式能改多个文件，适合中大型改造
- 内置终端、diff 预览，交互做得最好
- 某些场景下的提示词和上下文组织确实比通用模型更有效

问题也明显：**贵**。基础版 ¥140/月，重度使用会遇到额度限制；团队多人用成本很快上来。

适合：**一个人负责一个完整模块、需要频繁跨文件改动的开发者**。

### 3. Claude Code：长任务和终端工作流

我是通过中转渠道开始用 Claude Code 的，最大感受是：

- 在终端里直接读仓库、改文件、跑测试，工作流很顺
- 长任务不容易“聊着聊着忘了目标”
- 配合 Skill、脚本、Git 操作，适合做“工程化”的活
- 接进 Obsidian 后，查笔记、整理文档也方便

但要注意：

- 中转渠道的能力和稳定性不一定等于官方
- 代码会离开本地，敏感项目要谨慎
- 长任务 token 消耗快，月底账单容易超

适合：**能接受终端操作、需要 Agent 做完整任务的人**。

### 4. OpenCode：模型自由，成本可控

OpenCode 对我的价值是“模型可选”：

- 可以接国内模型 API，也可以接 GitHub Copilot
- 适合按任务选模型：简单活用小模型，复杂活用强模型
- 阿里云 Coding Plan 之类的套餐价格有优势
- 终端交互和 Claude Code 类似，学习成本不高

问题：

- 生态、插件、文档还不如头部产品成熟
- 不同模型的工具调用能力差异大，需要自己调
- 中转/套餐的稳定性和隐私要自己评估

适合：**愿意折腾、想控成本、需要接国内模型的团队**。

### 5. 免费模型：别小看

豆包、DeepSeek、ChatGPT、Gemini 的免费额度，足够覆盖：

- 查 API 用法、报错原因
- 写正则、SQL、脚本片段
- 生成配图、封面、简单素材
- 方案对比和文字润色

我的体感是：**Gemini 在时效性和客观性上更稳，生成图片也好用；DeepSeek 中文技术问题响应快；ChatGPT 适合综合讨论；豆包手机端方便。**

但它们不适合替代仓库级 Agent：上下文、文件读写、命令执行都需要专门工具。

## 三、怎么选：按场景而不是按排名

### 场景 1：个人开发者，预算有限

```text
Copilot（¥70）+ 免费模型
```

补全和问答分开，成本最低。需要重构时再临时开一个 Agent。

### 场景 2：一个人负责完整项目

```text
Cursor（¥140）或 Claude Code（¥50 中转）
```

重点是“跨文件”和“能跑命令”。Cursor 交互更顺，Claude Code 终端工作流更强。

### 场景 3：小团队，想控成本

```text
Copilot 团队版 + OpenCode/国内模型
```

补全统一用 Copilot，Agent 按任务选模型。注意统一代码规范和安全边界。

### 场景 4：企业私有化/敏感项目

- 不要用不可控中转
- 优先私有化部署或企业版
- 代码脱敏、权限隔离、审计日志
- 模型能力可以稍弱，但数据不能出内网

## 四、成本控制的几个经验

1. **不要同时订阅三个 Agent**  
   功能重叠很高，先把一个用透。

2. **补全和 Agent 分开**  
   补全用便宜的，Agent 按任务开，别让补全工具承担重构。

3. **长任务先写计划**  
   让 Agent 先输出步骤和影响文件，确认后再改，能省很多 token。

4. **小心“聊天式重构”**  
   大段贴代码让模型改，既贵又容易丢上下文。用仓库级工具，或者先缩小范围。

5. **中转渠道只用于非敏感项目**  
   价格便宜，但稳定性和隐私不可控。企业代码不要赌。

## 五、2026 年下半年的变化

- Agent 产品从“补全”转向“能执行任务”，终端类工具越来越多
- 国内模型价格继续下探，OpenCode 这类多模型客户端的性价比更明显
- IDE 内置 Agent 越来越强，单纯补全工具的差异化变小
- 企业采购开始关注“代码是否出内网”，私有化部署需求上升

## FAQ

**Q：Copilot 和 Cursor 需要同时买吗？**  
A：预算允许可以，补全和 Agent 是两种工作流。预算有限就二选一，优先 Agent。

**Q：Claude Code 中转靠谱吗？**  
A：非敏感项目可以尝试，但要接受稳定性、隐私和封号风险。企业项目不建议。

**Q：OpenCode 能替代 Claude Code 吗？**  
A：日常任务可以，复杂长任务和生态成熟度还有差距。看你的模型和配置。

**Q：免费模型够用吗？**  
A：查资料、写片段、生成图片够用；仓库级改造不够。
